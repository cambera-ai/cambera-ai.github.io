## How this site is published

GitHub Pages is configured as `build_type: legacy`, source **`main` / `/`** — and that is the
only thing it serves. A branch alone is **not** reachable on the web, so versions are switched
by moving the `main` ref, not by reconfiguring Pages.

| Branch | What it is |
|---|---|
| `main` | whatever is live right now |
| `site/teaser-mission` | current version: hero (eyebrow + tagline + subtitle) and the `#mission` section, EN + PL |
| `site/teaser` | frozen previous version (single-screen teaser3, no mission section), EN + PL — the rollback point |

**Publish / roll back** — repoint `main` at the chosen commit:

```
gh api repos/cambera-ai/cambera-ai.github.io/git/refs/heads/main \
  -X PATCH -f sha=<commit> -F force=true
```

Pages rebuilds itself in 30–40 s. Verified in both directions on 2026-09-06 (forward and
backward), including the backward move that needs `force`.

Always confirm the result against the live URL, not against the API response:

```
curl -s https://cambera-ai.github.io/ | md5sum   # must equal md5sum of index.html on that branch
```

## Languages

Two languages, two URLs, no JavaScript: `/` is English, `/pl/` is Polish. The switcher
sits in the header of both pages, and `<link rel="alternate" hreflang>` plus `canonical`
tell crawlers they are the same page.

The H1 tagline **is translated**: `/pl/` says „Wlewamy inteligencję w konstrukcję.”
(Jakub, 2026-09-08 — this supersedes the earlier „tagline stays in English” decision of
2026-09-06). All wording on both pages quotes `obsidian-vault/Cambera/MISSION.md`.

`/pl/` exists on **every** `site/*` branch, so moving `main` between versions never leaves
the Polish URL as a 404.

## Files

- `index.html` — the English page (single file: inline CSS, no build step)
- `pl/index.html` — the Polish page; asset paths are `../assets/…`, `og:url` ends with `/pl/`
- `assets/cambera-symbol-dark.svg`, `assets/cambera-wordmark-light.svg` — copies from
  `cambera-assets/assets/`; **never edit them here**, regenerate there and copy
- `404.html` — branded not-found page, bilingual, served by Pages for any unknown path;
  its asset paths are **absolute** (`/assets/…`), because it also answers deep URLs
- `robots.txt`, `sitemap.xml` — both URLs with `hreflang` alternates; update `lastmod`
  when the copy changes
- `favicon.png`, `apple-touch-icon.png`, `og.png` / `og-pl.png` (1200×630) — generated by
  `cambera-assets/scripts/icons.py`
- `assets/fonts/*.woff2` — **self-hosted** Space Grotesk + JetBrains Mono (`latin`,
  `latin-ext`; the Polish page needs `latin-ext`). No request leaves for Google Fonts —
  the site sells trust to EU plants, so it must not call a US CDN on load. Licences and
  the refetch recipe: `assets/fonts/README.txt`
- No `mailto:` anywhere: `hello@cambera.ai` bounces (the `cambera.ai` domain is not
  registered), so the Tally form is the only contact path. Restore the address only
  together with a working mailbox
- Asset paths must stay relative; `og:image` must stay absolute

Any brand or narrative change here also requires updating row 9 of
`cambera-assets/PROPAGATION.md` in the same step.
